# はじめに
みなさん、お疲れ様です。
今回は様々な認証方法がある中で業務でも活用しているGoogle Authernticatorが気になったので理解を深める為に深掘りしていきます。
「QRコード読み取って数字が出てくるやつでしょ？」そんな方も多いのではないでしょうか。
とはいえ、インターネットに繋がってなくてもワンタイムパスワードを生成できるし、アプリを起動すると既にコードは生成されているし...
意外と謎な部分が多い、Google Authenticatorの基本から仕組み等を書いていきたいと思います。

## Google Authenticatorって何？ 
Google Authenticatorは、**2段階認証（2FA: Two-Factor Authentication）** を行うためのアプリです。
簡単に言うと、「パスワードだけじゃなくて、もう1つ別の方法で本人確認をするで」というセキュリティ対策のためのツールです。

![](https://storage.googleapis.com/zenn-user-upload/466637760e86-20251119.jpg) 

**30秒ごとに変わる6桁の数字**が表示されます。対象のサービスと連携させてこの数字を入力することでログインできるようになります。

### Google Authernticatorについて
Google Authenticatorは2010年にGoogleによって公開され、Android・iOSなど多くのプラットフォームで利用できるアプリです。
主にTOTP（Time-based One-Time Password、RFC 6238）とHOTP（HMAC-based One-Time Password、RFC 4226）の仕組みに基づいており、ワンタイムパスワード（OTP）を生成します。
アカウントごとに「シークレットキー」と呼ばれる秘密情報がデバイスと認証サーバで共有されます。このキーは、QRコードをスマホで読み取ることでGoogle Authenticatorアプリに取り込まれます。

## どんな仕組みで動いているの？
 
さあ、ここからが本題です。「なんで30秒ごとに数字が変わるの？」「どうやって本人確認してるの？」という疑問を調べていきます。
たまに30秒ギリギリで点滅した時点でも最後の6桁を入れてEnterを押すと認証されて、ログイン出来るという点が個人的には感動です。
いや、ログイン当たり前でしょって思った方はすいません。
結論から行くとクライアント側でアプリで生成されているパスワードと認証サーバがデータベースに保存されている同じパスワードがTOTPの同じアルゴリズムで30秒毎に生成されており
入力値とデータベースの保存値を比較し一致すれば認証するというものでした。
![](https://storage.googleapis.com/zenn-user-upload/61899afc137e-20251119.png)

### TOTP（Time-based One-Time パスワード）という技術

Google Authenticatorは**TOTP**という技術を使っています。日本語にすると「時間ベースのワンタイムパスワード」です。

名前の通り、**時間**を使ってパスワードを生成する仕組みです。

### 仕組みの概要


以下の要素を組み合わせて、6桁の数字を作り出しています：

1. **シークレットキー**（QRコードに含まれている秘密の情報）

2. **現在時刻**（30秒単位）

3. **HMAC-SHA1**という暗号化アルゴリズム

 

```
ワンタイムパスワード = TOTP(シークレットキー, 現在時刻)
```

 

### もう少し詳しく

 

#### ステップ1: シークレットキーの共有

 

最初にQRコードを読み取った時、実は**シークレットキー**というランダムな文字列が、サービス側とアプリの両方に保存されます。

 

```
例: JBSWY3DPEHPK3PXP
```

 

このシークレットキーは、サービス側とあなたのスマホだけが知っている「秘密の合言葉」みたいなものです。

 

#### ステップ2: 時刻を30秒単位に丸める

 

現在のUnixタイムスタンプ（1970年1月1日からの秒数）を30で割ります。

 

```
タイムステップ = 現在のUnixタイムスタンプ ÷ 30
```

 

例えば：

- 2026年1月1日 12:00:00 → タイムステップ: 57283200

- 2026年1月1日 12:00:29 → タイムステップ: 57283200（同じ）

- 2026年1月1日 12:00:30 → タイムステップ: 57283201（変わる！）



 

#### ステップ3: HMAC-SHA1で暗号化

 

シークレットキーとタイムステップを使って、HMAC-SHA1というアルゴリズムで計算します。

```
ハッシュ値 = HMAC-SHA1(シークレットキー, タイムステップ)
``` 

この計算結果から6桁の数字を取り出します。

#### ステップ4: 6桁の数字を表示
 
最後に、計算結果から6桁の数字を抽出して表示します。

```
123456
```

### サービス側も同じ計算をしている

重要なポイントは、**サービス側も全く同じ計算をしている**ということです。

1. サービス側はシークレットキーを持っている

2. サービス側も現在時刻がわかる

3. 同じアルゴリズムで計算する

この仕組みにより入力した6桁の数字と、サービス側が計算した数字が**一致すれば本人確認完了**となるわけです。

## なぜ安全なの？
 
### オフラインで動く

Google Authenticatorは**インターネット接続不要**で動きます。スマホ内で計算が完結するので、通信を傍受されても安全です。

 

### 30秒で無効になる

 

パスワードが30秒ごとに変わるので、たとえ誰かに見られても、すぐに使えなくなります。

 

### シークレットキーは外部に出ない

 

シークレットキーはスマホとサービス側にしか保存されていません。QRコード読み取り後は、インターネットに送信されることはありません。

 

### 推測が不可能

 

暗号化アルゴリズム（HMAC-SHA1）により、シークレットキーを知らない人が次の数字を予測することは事実上不可能です。


## 注意点

 

### バックアップを忘れずに！

 

スマホを紛失したり、機種変更する時のために、**バックアップコード**や**QRコードのスクリーンショット**を安全な場所に保存しておく。

 

### 時刻のズレに注意

 

スマホの時刻が大幅にズレていると、正しいコードが生成されません。自動時刻設定をONにしておくことをおすすめ。


## まとめ

 

Google Authenticatorは、時間とシークレットキーを使って30秒ごとに変わる6桁の数字を生成する、シンプルでありながら強力なセキュリティツールです。

 

**ポイントのおさらい：**

 

- 2段階認証でセキュリティを大幅強化

- TOTPという時間ベースの仕組みを使用

- オフラインで動作するから安全

- シークレットキー + 現在時刻で計算

- 30秒ごとに新しいコードを生成

 
まだ使っていない方は、ぜひGoogle Authenticatorを導入してみてください！

セキュリティは面倒に感じるかもしれませんが、一度設定すれば、あとは数字を入力するだけ。この小さな手間が、アカウントを守ってくれと思えば活用する価値はあると思います。
